# Architecture Review
Generated: 2026-10-05T18:15:31.914Z
Score: 66/100

## Summary
The codebase is small and layered cleanly: pure date and accrual logic in lib/, thin wrappers around the Toss SDK, and a few pre-built UI primitives. No circular dependencies are visible. The main weaknesses are a stale contract.ts whose types contradict the real types.ts, the same helpers copy-pasted across files (todayYmd, haptics, SDK try/catch guards), mixed import and quoting conventions between scaffold files and app files, and lib/ and components/ each mixing generic, platform-SDK and domain code. A fair amount of scaffold code (MiniBar, Sparkline, TossPurchase, AdSlot, FloatingTabBar, CountUp, Amount) looks unused.

## Issues
### Critical
- [consistency] contract.ts declares data shapes that contradict the real model in types.ts. AppInput has joinDate/monthlyWage in contract.ts but hireDate/basis/monthlySalary in types.ts. LeaveBucket has startDate/daysInTenths vs kind/grantedDate/remainingTenths. AppResult has dDay: number and expiringAmountKrw vs dDay: number|null and expiringAmount. BridgeCombo and MonthPlan differ as well. Function contracts also disagree: parseYmdFn returns string|null while parseYmd returns a Ymd object, and recommendBridgesFn has a different parameter order than recommendBridges. The file claims to be the source of truth ('do not modify'), so it is a trap for anyone who imports from it. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/date.ts, src/lib/bridges.ts, src/lib/summary.ts / Fix: Delete contract.ts, or regenerate it from types.ts so it cannot drift. The real modules should be the only source of truth. If the generator must keep emitting it, exclude it from the build and from tsc, and add a type-level test (e.g. `satisfies`) that fails when the signatures diverge.

### Warnings

Replace all local copies. Pages and components should import it instead of re-implementing it.
- [duplication] The 'fire haptic safely outside the WebView' try/catch + Promise.resolve(...).catch pattern is implemented three times: fireHaptic in BottomCTA, tickWeak in Home, and inline in FloatingTabBar. Have every component and page use these instead of repeating the try/catch.
- [naming] Import specifiers are inconsistent. Scaffold files use relative paths ('../lib/utils', './storage'), app files use the '@/lib/...' alias, and Home/Result mix both ('../components/Card' next to '@/components/TossRewardAd'). Quote style also splits between scaffold files (double quotes) and app files (single quotes). Aliases such as `validateInputOptionalSalary as validateInput` hide which validator is in use. — Files: src/pages/Result.tsx, src/pages/Home.tsx, src/components/PageShell.tsx, src/components/Amount.tsx, src/components/DeepTier.tsx, src/lib/review.ts, src/lib/bridges.ts, src/lib/accrual.ts / Fix: Standardize on the '@/' alias for cross-directory imports and relative paths only within the same folder. Enforce this with an ESLint import rule, and format with Prettier (one quote style). Rename `validateInputOptionalSalary` to `validateInput` and the strict variant to `validateInputStrict`, or merge them with an `{ salaryOptional }` option.
- [dead_code] Several exports appear to be used nowhere in the 37 files shown: MiniBar, Sparkline, FloatingTabBar, AdSlot, TossPurchase, SummaryHero's `ai` prop (and probably CountUp/Amount), `cn` and `formatCurrency` in lib/utils.ts, the `HOLIDAYS`/`holidays` alias, the `saveAppInput`/`loadAppInput` aliases, `Ymd`, and `parseYmdFn` and the other `*Fn` types in contract.ts. Within the pages, imports such as Chip/ChipItem/Paragraph in Home and Button/Paragraph in other files are likely unused, so run lint on them. These are template components whose rules say 'Pre-built (do not reimplement)', but they ship dead weight and extra SDK surface (IAP, ads) into a bundle that has a size limit. — Files: src/components/MiniBar.tsx, src/components/Sparkline.tsx, src/components/FloatingTabBar.tsx, src/components/AdSlot.tsx, src/components/TossPurchase.tsx, src/components/CountUp.tsx, src/components/Amount.tsx, src/lib/utils.ts, src/lib/holidays.ts, src/lib/inputStore.ts, src/lib/contract.ts / Fix: Verify with knip or ts-prune. Remove unused components and utilities, or move template-only components to a separate `components/_kit` folder that is excluded from the app and imported only when needed. - [consistency] Storage error handling is asymmetric. `getItem` swallows errors, but `setItem` and `removeItem` throw. Callers then compensate (inputStore wraps setItem and removeItem in try/catch, review.ts wraps setItem and even comments that 'storage.setItem has no guard'). The result is a try/catch at every call site and ambiguity about whether any storage call can throw. A similar split exists across the SDK wrappers: some swallow everything (analytics, share), some pass errors to onError (TossPurchase), and TossRewardAd fails open by contract. — Files: src/lib/storage.ts, src/lib/inputStore.ts, src/lib/review.ts / Fix: Make all three storage functions in storage.ts non-throwing and return a success boolean from setItem and removeItem. Remove the redundant try/catch blocks in inputStore.ts and review.ts. Document the error policy in one place (e.g. lib/README) and apply it uniformly to the SDK wrappers.
- [structure] lib/ mixes three concerns: pure domain logic (accrual, bridges, plan, summary, date, holidays, validation), platform/SDK wrappers (analytics, review, share), and generic utilities (utils, storage). components/ similarly mixes generic UI primitives (Card, Amount, MiniBar), SDK-bound widgets (AdSlot, TossRewardAd, TossPurchase) and a domain component (DeepTier) that contains calculation (`compute`), formatting helpers (monthDay, monthLabel, days) and analytics. Result.tsx (288 lines) and Home.tsx (204 lines) also embed constants (NOTICES, KIND_LABEL, BASIS_OPTIONS) and parsing logic (readInput, digitsToYmd) that belong outside the page. — Files: src/lib/analytics.ts, src/lib/review.ts, src/lib/share.ts, src/lib/accrual.ts, src/components/DeepTier.tsx, src/components/TossRewardAd.tsx, src/pages/Result.tsx, src/pages/Home.tsx / Fix: Split lib/ into lib/domain (date, holidays, accrual, bridges, plan, summary, validation, types), lib/platform (analytics, review, share, storage, haptic) and lib/format (formatNumber, monthDay, monthLabel, days). Split components/ into components/ui, components/toss (SDK widgets) and features/result (DeepTier). Move `compute` and its date-format helpers out of DeepTier into lib, and move readInput and the constants out of the pages.

### Suggestions
- [duplication] CountUp and Amount render the identical nowrap/tabular-nums span wrapper and Paragraph.Text with formatNumber. The only difference is the animated value. The Card gap/Spacing handling is also duplicated against SummaryHero, which wraps content in Spacing by hand. — Files: src/components/Amount.tsx, src/components/CountUp.tsx, src/components/SummaryHero.tsx, src/components/Card.tsx / Fix: Have CountUp compute the animated number and render `<Amount value={display} .../>` so the style lives in one place. Optionally extract a `useCountUp(value, durationMs)` hook.
- [duplication] The validate-input → summarize pipeline appears in both Home (submit) and Result (readInput re-validates and recomputes), and both alias `validateInputOptionalSalary as validateInput`. RouteState also carries `result`, which Result appears to recompute anyway, so there are two sources of truth for the result. — Files: src/pages/Home.tsx, src/pages/Result.tsx, src/lib/validation.ts, src/lib/types.ts / Fix: Pick one: pass only `input` in route state and compute the result in Result, or pass the result and trust it. Move the 'validate then summarize' step into a single lib function (e.g. `computeResult(input, today)`).
- [naming] Units and names are mixed in the data model. `usedDays` is in days (0.5 steps), while every other quantity is in tenths (`*Tenths`, `tenths`). `MonthPlan.tenths` vs `AppResult.totalRemainingTenths` vs `LeaveBucket.grantedTenths`. BottomCTA.tsx exports `SubmitFooter` and `ButtonStack` (the file name doesn't match its exports). inputStore.ts exposes both `saveInput` and the alias `saveAppInput`, and holidays.ts exposes both `HOLIDAYS` and `holidays`. — Files: src/lib/types.ts, src/components/BottomCTA.tsx, src/lib/inputStore.ts, src/lib/holidays.ts / Fix: Rename `usedDays` to `usedDaysInput`, or convert it to `usedTenths` at the boundary and use tenths everywhere internally. Rename BottomCTA.tsx to match its exports (or split it into SubmitFooter.tsx and ButtonStack.tsx). Delete the duplicate alias exports once contract.ts is gone.
- [consistency] PageShell and Card use test-mock-defensive patterns (`import * as RouterDom` + `pick()` with try/catch, `Tds.Spacing` read at module load, `useInRouter` and `useScreenLog` resolved by namespace lookup). This is accidental complexity driven by test-harness quirks. It defeats static analysis and tree-shaking guarantees, and makes the hook order depend on module-load-time probing. Styling approaches are also mixed: inline style objects in most components, but CSS classes in TossRewardAd (reward-ad.css) and AdSlot ('ad-slot'), and a `className` prop on TossPurchase. — Files: src/components/PageShell.tsx, src/components/Card.tsx, src/components/TossRewardAd.tsx, src/components/AdSlot.tsx, src/components/TossPurchase.tsx / Fix: Import `useInRouterContext` and `useScreenLog` normally and fix the test mocks with a shared `mockAnalytics()`/router helper (use `vi.mock(..., async (orig) => ({...await orig(), ...}))`). For Card, detect the Spacing child with a data attribute or a prop instead of probing the TDS export. Pick one styling approach (inline tokens or CSS modules) and use it consistently.
- [consistency] Domain data is hard-coded and partly unverified: holidays.ts carries a 'must be checked against the official calendar before release' warning, and `HOLIDAY_COVERAGE_END` is duplicated as a filter inside recommendBridges even though the `holidays` argument is already injected. The 209 divisor, 8-hour day and the 15..25 day accrual rule are magic numbers in summary.ts and accrual.ts. — Files: src/lib/holidays.ts, src/lib/bridges.ts, src/lib/summary.ts, src/lib/accrual.ts / Fix: Move the constants (MONTHLY_HOURS = 209, DAILY_HOURS = 8, MAX_ANNUAL_DAYS = 25) into a `lib/domain/constants.ts`. Have the holiday module own the coverage filter and export a single `getHolidays()`, so recommendBridges does not re-filter. Add a release checklist item or test that fails when today is past HOLIDAY_COVERAGE_END.
- [circular_dep] No circular imports were found. The dependency graph is acyclic: pages → components → lib; lib/domain modules depend only on date/types/holidays. Watch for one risk: components/PageShell imports lib/analytics while analytics must stay free of any component imports. — Files: src/components/PageShell.tsx, src/lib/analytics.ts / Fix: Keep lib/ free of imports from components/ or pages/. Add `eslint-plugin-import/no-cycle` or `madge --circular` to CI so the rule is enforced rather than relying on convention.

# Architecture Review
Generated: 2026-10-04T16:13:14.069Z
Score: 64/100

## Summary
The codebase is a small, mostly well-layered Vite + React + TDS mini-app. `lib/` holds pure logic, `components/` holds UI, and `pages/` holds screens. No circular dependencies are visible, and SDK access is defensively wrapped. It is held back by a stale `contract.ts` that contradicts the real domain types, a lot of unused scaffold code, copy-pasted helpers (today, haptics, input validation), inconsistent import and quote conventions, and test-mock workarounds embedded in production components. Result.tsx and Home.tsx were truncated in this review, so some dead-code and duplication findings are inferred from the visible parts.

## Issues
### Critical
- [consistency] `src/lib/contract.ts` is documented as the source of truth for cross-packet interfaces, but it contradicts the real implementation. AppInput uses joinDate/monthlyWage with no `basis`, while types.ts uses hireDate/monthlySalary/basis. LeaveBucket uses startDate/daysInTenths, versus kind/grantedDate/remainingTenths. AppResult, MonthPlan, BridgeCombo and RouteState all differ. Function signatures also differ: `recommendBridges`, `buildMonthlyPlan`, `validateInput` (returns null vs `{}`) and `summarize`. The file has no importers and has drifted from the code, so it is misleading. Anyone who follows it will build against the wrong shapes. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/bridges.ts, src/lib/plan.ts, src/lib/validation.ts, src/lib/summary.ts / Fix: Delete contract.ts, or regenerate it from `types.ts` and the real function signatures so it cannot drift. Better, make `types.ts` the only contract and re-export from it. Remove the alias exports (`saveAppInput`/`loadAppInput`, `holidays`/`HOLIDAYS`) that only exist to satisfy the stale contract.

### Warnings
- [duplication] `todayYmd()` is copy-pasted in Home.tsx and Result.tsx, and a local `pad` helper is re-implemented in both. `date.ts` already has private `pad`/`toYmd`/`fromDate`. accrual.ts (`String(year).padStart(4,'0')-01-01`) and plan.ts (month key building) hand-roll the same zero-padded formatting. — Files: src/pages/Home.tsx, src/pages/Result.tsx, src/lib/date.ts, src/lib/accrual.ts, src/lib/plan.ts / Fix: Export `todayYmd()` (or `fromDate`) and `toYmd` from `lib/date.ts`. Replace the local copies. In plan.ts, iterate months with `addMonthsClamp` instead of the manual year/month loop.
- [duplication] AppInput validation exists in three places. `inputStore.isAppInput` checks the stored shape and `Result.readInput` re-validates route state. `validation.validateInput` validates the form values. They apply slightly different rules (readInput checks hireDate > today, isAppInput does not). — Files: src/lib/inputStore.ts, src/pages/Result.tsx, src/lib/validation.ts / Fix: Create one `parseAppInput(unknown, today): AppInput | null` in `lib/validation.ts`, built on `validateInput`. Use it in inputStore.loadInput and in Result so shape and range rules live in one place.
- [duplication] The same 'SDK throws outside the WebView, so wrap in try/catch and `Promise.resolve().catch`' pattern is hand-written many times. These are BottomCTA.fireHaptic, FloatingTabBar's inline haptic, Home.tickWeak, AdSlot, TossPurchase, TossRewardAd, and the analytics, share and review wrappers. Haptics alone are implemented three times. — Files: src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/pages/Home.tsx, src/lib/analytics.ts, src/lib/review.ts, src/lib/share.ts, src/components/AdSlot.tsx / Fix: Add `lib/haptics.ts` (`haptic(type)`) and a small `lib/safeSdk.ts` (`safeCall`/`fireAndForget`). Have analytics, review, share and the components use them. Components should not import `generateHapticFeedback` directly.
- [dead_code] Many pre-built scaffold modules appear unused by the visible app: AdSlot, TossPurchase, FloatingTabBar, Sparkline, MiniBar, Amount, CountUp and ButtonStack. The same goes for `cn` and `formatCurrency` in utils.ts, the `saveAppInput`/`loadAppInput` aliases, and the `HOLIDAYS` export (only used to build the `holidays` alias). They add bundle and maintenance surface. Some also carry long prose in their JSDoc. — Files: src/components/AdSlot.tsx, src/components/TossPurchase.tsx, src/components/FloatingTabBar.tsx, src/components/Sparkline.tsx, src/components/MiniBar.tsx, src/components/Amount.tsx, src/components/CountUp.tsx, src/lib/utils.ts, src/lib/inputStore.ts, src/lib/holidays.ts / Fix: Confirm with a usage search (Result.tsx was truncated). Remove components and helpers with no consumers, or move the intentionally kept template components to a clearly labelled `components/kit/` or `_template/` folder excluded from the build. Drop the unused aliases.
- [structure] `components/` mixes three kinds of module: generic UI (Card, MiniBar, StateView), SDK wrappers (AdSlot, TossPurchase, TossRewardAd) and a domain feature component (DeepTier). DeepTier depends on lib/bridges, plan, holidays and analytics and is only used by Result. Home.tsx and Result.tsx also carry business logic (view-state machine, `readInput`, mask/touch handling) inline, which makes them 200+ lines each. — Files: src/components/DeepTier.tsx, src/pages/Result.tsx, src/pages/Home.tsx, src/components/TossRewardAd.tsx / Fix: Move DeepTier next to its page (`pages/Result/DeepTier.tsx` or `features/deep-plan/`). Put SDK wrappers in `components/toss/` or `lib/toss`. Extract page logic into hooks such as `useResultView` and `useHomeForm`. Keep `components/` for generic UI.
- [naming] Import path style is inconsistent, sometimes within one file. Result.tsx and Home.tsx mix `../components/...` with `@/components/...` and `@/lib/...`. DeepTier uses `./Card` plus `@/lib`. PageShell, Amount and CountUp use `../lib/...`. review.ts uses `./storage`, while accrual and summary use `@/lib/...`, and bridges.ts and plan.ts use `./types`. Quote style is also split: components, analytics, share and review use double quotes, while the rest of lib, pages and App use single quotes. — Files: src/pages/Result.tsx, src/pages/Home.tsx, src/components/DeepTier.tsx, src/components/PageShell.tsx, src/lib/review.ts, src/lib/bridges.ts, src/lib/plan.ts, src/lib/analytics.ts / Fix: Pick `@/` for cross-directory imports and `./` only for same-folder siblings. Enforce this with ESLint `no-restricted-imports` or `import/no-relative-parent-imports`. Add Prettier with `singleQuote` and run it across the repo.
- [consistency] Test-mock workarounds are baked into production code. PageShell's `pick()` and the Card `SPACING_TYPE` IIFE wrap module-level namespace reads in try/catch to survive partial `vi.mock` factories. Namespace imports (`import * as RouterDom`, `import * as Tds`, `import * as AnalyticsLib`) also undercut the claimed tree-shaking. This hides real import errors and adds long explanatory comments to the runtime path. — Files: src/components/PageShell.tsx, src/components/Card.tsx / Fix: Fix this on the test side: shared `mockAnalytics()` / `mockRouter()` helpers or `vi.mock` with `importOriginal`. Then use normal named imports (`useInRouterContext`, `useScreenLog`, `Spacing`) in the components.
- [consistency] Error handling and storage semantics are inconsistent. `storage.getItem` swallows errors but `setItem` and `removeItem` throw, so every caller must add its own try/catch (inputStore, review, inputStore.clearKey). review.ts's comment notes setItem is unguarded. `getItem<T>` returns an unchecked `JSON.parse` cast. `validateInput` returns `{}` for valid input where contract.ts says null. Some SDK failures are silent, while others (TossPurchase) route to onError. — Files: src/lib/storage.ts, src/lib/inputStore.ts, src/lib/review.ts, src/lib/validation.ts / Fix: Make storage.ts safe on all three operations (try/catch, return boolean or void). Remove the redundant try/catch in callers. Return `unknown` from getItem, or accept a validator. Document one error policy: SDK wrappers never throw, and domain functions return result objects.

### Suggestions
- [duplication] Amount and CountUp duplicate the `Typography` type alias, the identical nowrap/tabular-nums span style and the number+unit rendering. Only the value source differs. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Make CountUp render `<Amount value={display} .../>`. - [structure] A dev-only gallery lives in `pages/` with a `__` prefix. It is lazy-loaded behind `import.meta.env.DEV`. This works, but a naming trick is the only thing that marks it as non-production. — Files: src/pages/__TdsGallery.tsx, src/App.tsx / Fix: Move it to `src/dev/TdsGallery.tsx` so the production pages directory contains only real screens.
- [naming] Duplicate or alias exports and vocabulary drift: `HOLIDAYS` and `holidays`, `saveInput` and `saveAppInput`. The tenths concept is named `tenths`, `grantedTenths`, `remainingTenths`, `totalRemainingTenths`, `daysInTenths` and `allocatedTenths`. MonthPlan uses the bare `tenths`. — Files: src/lib/holidays.ts, src/lib/inputStore.ts, src/lib/types.ts, src/lib/plan.ts / Fix: Keep one name per concept. Pick a single suffix convention (e.g. `*Tenths`) and rename MonthPlan.tenths accordingly.
- [consistency] Input rules disagree between layers. `maskUsedDays` allows one decimal digit (0.1 steps) and the AppInput type comment says 0.5-step, but validateInput rejects anything not a multiple of 0.5. Users can type values the form then rejects. Separately, `bridges.recommendBridges` takes `holidays` as a parameter yet imports `HOLIDAY_COVERAGE_END` from the holidays module directly, so it is only half dependency-injected. — Files: src/lib/inputMask.ts, src/lib/validation.ts, src/lib/bridges.ts / Fix: Either restrict the mask to .0/.5 or loosen validation. Pass the coverage end date into recommendBridges as well, or import both holidays and coverage from the module. Do not mix the two.
